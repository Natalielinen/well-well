<domain>
## Phase Boundary

Phase 03.1 исправляет баги, найденные при повторном картировании кода (`.planning/codebase/CONCERNS.md`, 2026-10-24), **до** Phase 4 (Testing), чтобы тесты фиксировали уже корректное поведение. Шесть зафиксированных требований:

- **BUGF-05** — выполнение неповторяющейся задачи отменяет её запланированное уведомление.
- **BUGF-06** — даты задач обрабатываются как локальные календарные дни через одну утилиту: нет сдвига на сутки в `WeekStrip`, фильтрах, на карточке и в логике повторения.
- **BUGF-07** — список обновляется сразу после выполнения задачи, независимо от того, как закрыт Alert.
- **BUGF-08** — выполнение задачи обновляет актуальную запись из хранилища по `id`, не затирая её устаревшим пропсом.
- **BUGF-09** — при сбое планирования напоминания задача сохраняется без напоминания, и пользователь об этом знает.
- **BUGF-10** — прошедшее время напоминания отклоняется валидацией в форме, а не переносится молча на +60 с.

Границы зафиксированы ROADMAP.md (§ Phase 03.1) и REQUIREMENTS.md. Новые возможности (отложенные напоминания, undo, синхронизация, перенос на ближайшую будущую дату) — вне области. Обсуждение уточняло **как** исправить, а не **что** добавить.

</domain>

<decisions>
## Implementation Decisions

### Прошедшее время напоминания (BUGF-10)
- **D-01:** Если при сохранении формы (`components/AddTodo/AddTodo.tsx`, `onCreate`) выбранное время напоминания уже прошло, задача **не сохраняется**, под полем напоминания показывается ошибка валидации (текст в духе «Время напоминания уже прошло»). Тот же паттерн, что у существующей проверки `minDate` («Дата не может быть в прошлом»): поле в `error`-state, `return` из `onCreate`.
- **D-02:** При включении напоминания в форме значение по умолчанию — **дата задачи (`nextDate`) + ближайший целый час от текущего времени** (например, 14:20 → 15:00). Заменяет текущее `setRemindDate(new Date())` (`AddTodo.tsx`, `useEffect` по `showRemindField`), которое гарантированно оказывалось в прошлом к моменту сохранения. Крайние случаи (23:xx, дата задачи в будущем) — на усмотрение планировщика, при условии что значение по умолчанию для задачи на сегодня всегда в будущем.
- **D-03:** При редактировании задачи проверка D-01 применяется **только если пользователь менял напоминание** (дату/время или включил его заново). Неизменённое уже прошедшее напоминание остаётся в данных как есть (`reminderDate` сохраняется — для повторяющихся задач это источник времени суток для следующих выполнений через `nextReminderIso`), но новое уведомление на прошедший момент **не планируется**.
- **D-04:** `getEffectiveReminderDate` (подмена прошедшего времени на now + 60 с в `hooks/useNotifications.ts`) **удаляется полностью**. Правило везде: уведомление на прошедший момент не планируется. Это касается и пути выполнения задачи: если после выполнения давно просроченной повторяющейся задачи («Дата в задаче») следующая дата всё ещё в прошлом, `reminderDate` сохраняется, а уведомление не создаётся — задача и так видна как «Просрочена». Перенос на ближайшую будущую дату НЕ делается (нарушил бы контракт единственного сдвига `repeatFrequency`).

### Сбой напоминания (BUGF-09)
- **D-05:** Если `scheduleNotification` падает при **создании или редактировании** задачи, задача сохраняется **без напоминания** (`reminderDate` и `notificationId` = `undefined`), пользователь видит Alert («Задача сохранена, но напоминание не установлено…»). Форма не держится открытой. Одинаково для `onAddTodo` и `onUpdateTodo` в `hooks/useTodos.ts` (сейчас оба оставляют `reminderDate` без уведомления).
- **D-06:** Текст сообщения различает причину: если уведомления запрещены (проверка через `Notifications.getPermissionsAsync()`), сообщение подсказывает разрешить уведомления в настройках; при любой другой ошибке — общий текст. Сообщения через `Alert.alert` (прецедент Phase 2, BUGF-02).
- **D-07:** Если сбой происходит при **выполнении повторяющейся задачи** (перепланирование следующего напоминания в `handleCompleteTask` / `rescheduleNextNotification`), выполнение всё равно засчитывается: задача переезжает на следующую дату, `reminderDate` и `notificationId` сбрасываются, показывается то же сообщение, что в D-05/D-06. Сейчас исключение не обрабатывается, старое уведомление уже отменено, а выполнение не сохраняется — это исправляется.

### Выполнение задачи (BUGF-05, BUGF-07)
- **D-08:** Alert-подтверждения после выполнения **остаются** с текущими текстами («Успешно…», дата следующего выполнения для повторяющихся). Список (`getAllTodos`) обновляется сразу после сохранения, а не в `onPress` кнопки «OK», — закрытие алерта тапом вне окна больше ни на что не влияет.
- **D-09:** В алерт выбора даты для просроченной / ещё не наступившей повторяющейся задачи («Сегодня» / «Дата в задаче») добавляется третья кнопка **«Отмена»** (`style: "cancel"`). Тап вне окна по-прежнему означает отмену; задача не выполняется.
- **D-10 (BUGF-05):** При выполнении неповторяющейся задачи её `notificationId` отменяется до удаления задачи — так же, как уже делает `onTaskDelete`.

### Границы поведения
- **D-11:** Контракт Phase 3/4 сохраняется: при выполнении повторяющейся задачи `repeatFrequency` прибавляется ровно один раз (`utils/recurrence.ts` — единственное место сдвига; см. `.planning/debug/recurring-notification-stops-after-complete.md`).
- **D-12:** Формат хранения не меняется: `nextDate` — строка `yyyy-MM-dd`, `reminderDate` — ISO. Миграция сохранённых данных не нужна — `nextDate` всегда записывается через `format(nextDate, "yyyy-MM-dd")` (`AddTodo.tsx`), сдвиг возникает только при чтении через `new Date("yyyy-MM-dd")` (UTC-полночь).

### Claude's Discretion
- **BUGF-06 (даты):** форма общей утилиты для календарных дат (например, `parseDateKey`/`toDateKey` в `utils/time.ts` на базе `date-fns` `parse`/`format` с `"yyyy-MM-dd"`) и перевод всех потребителей: `WeekStrip.hasTasksOnDate` (`toISOString`), `Todo.tsx` (`new Date(todo.nextDate)` в ветке «Дата в задаче», в тексте алерта и в дате на карточке), `utils/recurrence.ts` (`nextReminderIso` — `new Date(nextDate)`), `AddTodo.tsx` (`new Date(editData.nextDate)` при открытии редактирования), `utils/todoFilters.ts`. Требование: после фазы в коде нет `new Date("yyyy-MM-dd")` и `toISOString()` для календарных дат.
- **BUGF-08 (запись по id):** способ обновления актуальной записи (например, `patchTodo(id, partial)` в `storage/todoStorage.ts`, читающий текущую запись перед слиянием) — на усмотрение агента.
- Как определить «напоминание изменено» в D-03 (сравнение с исходным `editData.reminderDate` в форме или с `oldTodo` в `onUpdateTodo`) и нужно ли пересоздавать будущее уведомление при изменении только названия/описания (текст уведомления содержит `title`) — на усмотрение агента.
- Точные тексты сообщений об ошибках D-01/D-05/D-06 — на усмотрение агента, в стиле существующих русскоязычных текстов приложения.
- Ошибки `cancelNotification` при выполнении задачи (уведомление уже сработало / неизвестный id) не должны блокировать выполнение.

</decisions>

## Existing Code Insights

### Reusable Assets
- `utils/time.ts` (`parseTime`/`formatTime`) — место для общей утилиты календарных дат (BUGF-06).
- `utils/todoFilters.ts` — уже парсит `nextDate` локально через `date-fns` `parse(…, "yyyy-MM-dd", …)`; эталон правильного подхода.

- `AddTodo.tsx` — паттерн валидации `onCreate` (`setError({...error, minDate: …}); return;`) для D-01.

### Established Patterns
- Ошибки пользователю — `Alert.alert("Ошибка", …)` (`hooks/useTodos.ts`).

- Notifications: `scheduleNotification`/`cancelNotification`/`rescheduleNextNotification` экспортируются из `hooks/useNotifications.ts` как функции модуля (не только через хук).

### Integration Points
- `components/Todo/Todo.tsx` — `onTaskComplete`, `handleCompleteTask`, `showAlert`, `showAlertForExpiredTask` (BUGF-05/07/08, D-07…D-10), дата на карточке (BUGF-06).
- `hooks/useTodos.ts` — `onAddTodo`/`onUpdateTodo` (BUGF-09, D-03, D-05, D-06).
- `hooks/useNotifications.ts` — удаление `getEffectiveReminderDate` (D-04), поведение `scheduleNotification`/`rescheduleNextNotification` для прошедших дат.
- `components/AddTodo/AddTodo.tsx` — валидация и значение по умолчанию напоминания (D-01…D-03).
- `components/WeekStrip/WeekStrip.tsx` — `hasTasksOnDate` (BUGF-06).
- `storage/todoStorage.ts` — обновление по `id` (BUGF-08).
