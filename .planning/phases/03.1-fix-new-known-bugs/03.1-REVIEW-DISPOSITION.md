# Решения по замечаниям ревью

Исходное ревью: 6 BLOCKER (поле critical), 0 warning, 0 info. Два замечания — регрессии, четыре — прежние дефекты. Это классификация ошибок поведения, а не оценка уязвимостей безопасности.

| Finding | Severity | Disposition | Source |
|---|---|---|---|
| CR-01 | critical | fixed | Блокировка охватывает открытый диалог; выбор одноразовый, cancel/onDismiss снимают блокировку. Повторный callback ничего не изменяет. |
| CR-02 | critical | fixed | Дата повторно проверяется после await getPermissionsAsync до системного планирования. |
| CR-03 | critical | fixed | При смене isRepeat или nextDate обработчик отменяет устаревшее действие, обновляет список и предлагает повторить выполнение. |
| CR-04 | critical | fixed | patchTodo проверяет актуальные значимые поля предикатом после ожидания планировщика; конфликт не перезаписывает данные, новое уведомление отменяется по возможности. Общий mutex по-прежнему вне области. |
| CR-05 | critical | deferred | Прежняя проблема ошибки сохранения при немедленном закрытии формы. 03.1-04-PLAN, interfaces явно сохраняет void callbacks, вызов без await и onModalClose. Это не исправлено и не считается принятым пользователем риском: требуется отдельное изменение контракта сохранения, обработки ошибок и состояния формы. Проверить при перепланировании Phase 4. |
| CR-06 | critical | fixed | Неизменённая прошедшая nextDate допускается при редактировании; новая прошедшая дата по-прежнему запрещена. |

Повторная независимая проверка: 03.1-REVIEW-FOLLOWUP.md. Автоматические регрессии: scripts/verify-phase-03.1.cjs. Реальная доставка и отмена уведомлений, нативные диалоги и видимость ошибок ожидают UAT.

Рекомендации 03.1-UI-REVIEW.md по контрасту, доступности, типографике и индикатору занятости отложены: исходный аудит не заменяет визуальную проверку на устройстве, дополнительных UI изменений эта фаза не обещает.
