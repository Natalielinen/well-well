## Три приоритетных исправления

1. **F1 — повысить контраст ошибки.** Для текста `errorText` использовать отдельный тёмный семантический токен, например `#b91c1c`: расчёт на белом фоне даёт 6,47:1 вместо 3,76:1. Не требуется глобально перекрашивать все элементы `danger`.
2. **F2 — сделать напоминание и отказ сохранения доступными скринридеру.** Задать Switch имя «Напомнить», полю даты — назначение и текущее значение; объявлять новую ошибку средствами доступности соответствующей платформы. Проверить TalkBack и VoiceOver отдельно.
3. **F3 — связать ошибку с состоянием поля.** Условно применять стиль ошибки к кнопке даты по `error.remindDate`, сохраняя текст причины. Проверить возврат к обычному состоянию после изменения даты/времени и выключения переключателя.

## Подробные результаты

### 1. Тексты — 3/4

**WARNING F4, рекомендация по ясности:** `components/AddTodo/AddTodo.tsx:201` показывает «Время напоминания уже прошло». Причина конкретна и соответствует D-01, но действие для исправления не названо. Рекомендуемый вариант: «Время напоминания уже прошло. Выберите будущие дату и время». Проверить перенос длинной строки. Это улучшение текста, а не нарушение согласованной формулировки.

Подписи «Сегодня», «Дата в задаче», «Отмена» реализованы в `components/Todo/Todo.tsx:135`, `:141`, `:146`. Существующая кнопка `OK` и тексты успеха сохранены по D-08; универсальность `OK` не вынесена в дефект вопреки этому решению. Сообщения сбоя уведомления различают запрет и общую ошибку, подтверждают сохранение задачи и предлагают следующий шаг (`hooks/useNotifications.ts:68`).

### 2. Визуальная иерархия — 3/4

**WARNING F3:** новая ошибка рендерится непосредственно после кнопки даты (`components/AddTodo/AddTodo.tsx:366`, `:380`), но сама кнопка всегда получает только `styles.dateButton` (`:367`). Её рамка остаётся `colors.border` независимо от ошибки (`components/AddTodo/styles.ts:117`). По коду имеется сообщение об ошибке, но нет отдельного состояния оформления поля, упомянутого D-01. Добавить условный стиль рамки; оставить текст, чтобы состояние не передавалось одним цветом.

Порядок JSX подтверждает привязку сообщения к напоминанию, но не доказывает, что сообщение видно после нажатия «Сохранить» при любой прокрутке и размере шрифта. Положение нативных кнопок Alert, их переносы и визуальное выделение отмены без устройства не оценивались.

### 3. Цвет — 2/4

**WARNING F1:** `styles.errorText` использует `colors.danger` (`components/AddTodo/styles.ts:161`), то есть `#ef4444` (`themes/colors.ts:12`), на фоне контейнера `colors.surface = #ffffff` (`components/AddTodo/styles.ts:6`, `themes/colors.ts:15`). Расчёт по относительной яркости sRGB даёт **3,76:1**. Для этого мелкого текста предлагается целевой контраст не менее 4,5:1; вариант `#b91c1c` даёт **6,47:1**. Это расчёт пары заданных цветов, а не измерение скриншота.

В рассматриваемом блоке напоминания один Switch использует `primaryLight` для включённой дорожки и `primary` для включённого ползунка; один Text ошибки использует `danger`. У выключенного ползунка есть существующий литерал `#ffffff` (`AddTodo.tsx:355`). Массовое новое применение акцента в этом блоке не обнаружено. Распределение цветов 60/30/10 по площади экрана не измерялось и не объявляется соблюдённым.

### 4. Типографика — 3/4

**WARNING F5, рекомендация по читаемости:** новое блокирующее сообщение наследует `fontSize: 12`, `fontWeight: "500"` (`components/AddTodo/styles.ts:161`), тогда как значение даты имеет размер 16 (`:124`), подпись переключателя — 14/500 (`:57`). Для важного отказа сохранения сообщение получает минимальный размер активной формы. Рекомендуется размер 14 и проверка системного масштабирования; факт обрезания или нечитаемости на устройстве не установлен.

В непосредственно проверяемом блоке используются три размера: 12, 14, 16; явный вес один — 500, у даты вес системный. В файле стилей объявлены размеры 12, 13, 14, 16, 20 и веса 500, 600, 700, однако размер 13 относится к неиспользуемому здесь `priorityText`. Поэтому механический подсчёт всех деклараций не принят за доказательство чрезмерного числа размеров на экране. Новая ошибка не имеет `numberOfLines` или фиксированной высоты; фактические переносы требуют ручной проверки.

### 5. Отступы — 3/4

**WARNING F6:** дата и ошибка находятся внутри дополнительного `<View>` без стиля (`components/AddTodo/AddTodo.tsx:365`). `gap: spacing.xs` внешнего `inputGroup` (`components/AddTodo/styles.ts:30`) действует между его прямыми детьми, а не между кнопкой даты и Text внутри этого View. У `errorText` нет `marginTop` (`:161`), поэтому отдельный интервал между рамкой поля и ошибкой не задан. Добавить внутренний `gap: spacing.xs` либо локальный `marginTop: spacing.xs` для ошибки; не менять общий стиль всех ошибок без необходимости.

Шкала темы: 4/8/16/24/32 (`themes/colors.ts:47`). Проверяемый блок наследует промежуток группы 4, вертикальный padding строки Switch 8 и padding кнопки даты 14 (`components/AddTodo/styles.ts:31`, `:55`, `:122`). Значение 14 уже существовало, новый diff не вводит произвольных отступов. Фактические размеры зон касания и переносы не измерялись.

### 6. Взаимодействие — 2/4

**WARNING F2:** у Switch «Напомнить?» нет `accessibilityLabel` или явной связи с соседним Text (`components/AddTodo/AddTodo.tsx:351`). Рядом есть и другой Switch, поэтому полагаться только на системную роль и значение недостаточно для однозначного назначения. Кнопка даты содержит лишь значение (`:366`), без доступного пояснения «Дата и время напоминания». Новый Text ошибки (`:381`) не имеет механизма объявления изменения; после отказа сохранения код только меняет state (`:201`), не перемещает доступный фокус и не объявляет причину. Риск: пользователь скринридера слышит отказ без объяснения либо вынужден искать его вручную. Отсутствие этих свойств доказано кодом; фактическое озвучивание не проверено. Добавить имя Switch, описание поля и платформенное объявление ошибки, исключив двойное озвучивание.

**WARNING F7:** новые функции завершения блокируют повторный вызов через `isCompletingRef` (`components/Todo/Todo.tsx:38`, `:41`, `:67`), но ref не отражается в JSX: чекбокс остаётся без `disabled`, `accessibilityState.busy` и видимой индикации (`:188`). При задержке системного API или хранилища повторный тап молча игнорируется. Добавить состояние ожидания для представления, сохранив ref как немедленную защиту, и сбрасывать его в `finally`. Это рекомендация обратной связи, не требование mutex хранилища.

Статически подтверждено:

- Ошибка ставится до вызова сохранения и закрытия формы (`AddTodo.tsx:198`); выводится под полем, а не только во внутреннем state (`:380`).
- Переключение очищает ошибку, закрывает оба пикера, выключение сбрасывает дату, включение задаёт новое значение (`AddTodo.tsx:60`).
- Отмена пикера не меняет дату/время напоминания (`AddTodo.tsx:126`, `:140`). Изменение значения очищает сообщение; окончательная проверка повторяется при сохранении.
- Неизменённое прошедшее напоминание исключено из новой проверки (`AddTodo.tsx:198`); планировщик пропускает прошлую дату до проверки разрешений (`hooks/useNotifications.ts:23`).
- У «Отмена» нет обработчика выполнения, задан `style: "cancel"`; у Alert выбора даты — `cancelable: true` (`Todo.tsx:146`). Реальное закрытие по внешнему тапу/системной кнопке проверяется на Android; нельзя переносить это обещание на iOS без проверки.
- Обновление списка предшествует сообщению об успехе (`Todo.tsx:56`, `:96`); `OK` больше не вызывает обновление (`:119`). Сбой напоминания не перекрывается вторым Alert успеха (`:98`).

Новые loading/empty-экраны этой фазой не заявлены; отсутствие таких экранов не оценивалось как нарушение её области.
